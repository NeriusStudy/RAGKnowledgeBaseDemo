## ✅ 步骤02：实现 VectorDB（向量数据库）

**任务状态**：已完成并测试通过 ✅

### 任务目标
实现基于语义理解的向量检索数据库，使用 DashScope 嵌入模型将文档转换为向量，并使用 Chroma 进行持久化存储和相似度检索。

### 具体任务
1. 实现 `VectorDB` 类的所有核心方法
2. 集成 DashScope Embeddings（阿里云大模型平台）
3. 集成 Chroma 向量数据库进行持久化存储
4. 支持文档的增删操作（单个和批量）
5. 实现基于余弦相似度的向量检索
6. 支持自定义检索数量 k

### 实现方法
- **文件位置**：`VectorDB.py`
- **核心组件**：
  - DashScopeEmbeddings（嵌入模型：`text-embedding-v2`）
  - Chroma（向量存储和检索）
- **关键方法**：
  - `add_document(document)` - 添加单个文档
  - `add_documents(documents)` - 批量添加文档
  - `delete_document(md5)` - 根据 md5 删除单个文档
  - `delete_documents(md5_list)` - 批量删除文档
  - `search(query, k)` - 向量检索
  - `delete_me()` - 清理数据库
  - `get_embedding_model_name()` - 获取嵌入模型名称

### 技术要点
- 使用 `langchain_chroma.Chroma` 替代已弃用的 `langchain_community.vectorstores.Chroma`
- 使用 Document 的 metadata['md5'] 作为唯一 ID
- Chroma 自动进行持久化存储到本地目录
- 检索时使用 `similarity_search()` 方法

### 验证方式
- **测试脚本**：`test_scripts/test_vectordb.py`
- **测试内容**：
  1. 初始化 VectorDB
  2. 添加单个文档
  3. 批量添加 99 个文档
  4. 向量检索测试（查询："糖尿病的症状"）
  5. 删除单个文档
  6. 批量删除文档
  7. 清理测试数据

### 遇到的问题和解决
1. **问题**：Chroma 导入弃用警告
   - **解决**：改用 `from langchain_chroma import Chroma`
   
2. **问题**：模型不存在错误（Model not exist）
   - **解决**：将模型名从 `text-embedding-2` 改为 `text-embedding-v2`

### 完成标志

✅ 测试脚本运行成功

## ✅ 步骤04：实现 Reranker（重排序器）

**任务状态**：已完成并测试通过 ✅

### 任务目标
实现混合检索的重排序器，整合向量检索和关键词检索结果，使用 RRF 算法进行融合，并使用 DashScope Rerank API 进行精确排序。

### 具体任务
1. 实现 `Reranker` 类的所有核心方法
2. 实现 RRF（Reciprocal Rank Fusion）融合算法
3. 集成 DashScope Rerank API（使用 `qwen3-rerank` 模型）
4. 支持自定义权重配置
5. 实现降级策略（API 失败时降级到 RRF 结果）

### 实现方法
- **文件位置**：`Reranker.py`
- **核心组件**：
  - dashscope SDK（Rerank API）
  - RRF 融合算法（自实现）
- **关键方法**：
  - `rerank(query, vector_docs, keyword_docs, weights, k)` - 两阶段重排序
  - `_rrf_fusion(vector_docs, keyword_docs, weights, k)` - RRF 融合算法
  - `get_rerank_model_name()` - 获取重排序模型名称

### 技术要点
- **两阶段重排序**：
  1. **粗排（RRF 融合）**：融合向量和关键词检索结果，去重
  2. **精排（Rerank API）**：使用深度学习模型精确排序
- **RRF 算法**：`score = vector_weight/(k+rank_v) + keyword_weight/(k+rank_k)`
- **降级策略**：API 失败 → RRF 融合结果 → 向量检索结果
- **工作空间支持**：支持配置 `DASHSCOPE_WORKSPACE_ID` 环境变量
- **直接使用 dashscope SDK** 而不是 LangChain 封装（更稳定）

### 验证方式
- **测试脚本**：`test_scripts/test_reranker.py`
- **测试内容**：
  1. 初始化 Reranker
  2. RRF 融合测试（不调用 API）
  3. 完整重排序测试（RRF + DashScope Rerank）
  4. 不同权重配置测试（0.7/0.3, 0.3/0.7, 0.5/0.5）
  5. 边界情况测试（空结果、只有向量、只有关键词）
  6. 清理测试数据

### 遇到的问题和解决
1. **问题**：`gte-rerank` 模型已下线（2026-05-30）
   - **解决**：更换为 `qwen3-rerank` 模型
   
2. **问题**：LangChain 的 DashScopeRerank 不支持工作空间
   - **解决**：改用 dashscope SDK 直接调用
   
3. **问题**：Rerank API 返回 None
   - **解决**：添加完整的异常处理和降级策略

## ✅ 步骤05：实现 RAGService（RAG统一服务）

**任务状态**：已完成并测试通过 ✅

### 任务目标
实现 RAG 统一服务接口，整合 VectorDB、KeywordDB、Reranker 三大核心组件，提供文档管理和多模式检索功能。

### 具体任务
1. 实现 `RAGService` 类的所有核心方法
2. 整合 VectorDB、KeywordDB、Reranker 三个组件
3. 实现文档管理功能（增删操作，保证数据一致性）
4. 实现三种检索模式（vector、keyword、hybrid）
5. 提供统一的检索接口
6. 实现降级策略

### 实现方法
- **文件位置**：`RAGService.py`
- **依赖组件**：
  - VectorDB（向量检索）
  - KeywordDB（关键词检索）
  - Reranker（重排序）
- **关键方法**：
  - `add_document(document)` - 添加单个文档（带一致性保证）
  - `add_documents(documents)` - 批量添加文档
  - `delete_document(md5)` - 删除单个文档
  - `delete_documents(md5_list)` - 批量删除文档
  - `_vector_search(query, k)` - 向量检索（内部方法）
  - `_keyword_search(query, k)` - 关键词检索（内部方法）
  - `_hybrid_search(query, k, weights)` - 混合检索（内部方法）
  - `search(query, mod, k, weights)` - 统一检索接口
  - `delete_me()` - 清理所有数据
  - `get_embedding_model_name()` - 获取嵌入模型名称
  - `get_rerank_model_name()` - 获取重排序模型名称

### 技术要点
- **数据一致性保证**：
  - 添加文档时，如果 KeywordDB 失败，自动从 VectorDB 回滚
  - 删除文档时，同时从两个数据库删除
- **三种检索模式**：
  1. **vector**：仅使用 VectorDB（语义检索）
  2. **keyword**：仅使用 KeywordDB（精确匹配）
  3. **hybrid**：VectorDB + KeywordDB + Reranker（推荐）
- **降级策略**：混合检索失败 → 向量检索
- **参数传递**：统一接口支持权重配置（vector_weight, keyword_weight）

### 验证方式
- **测试脚本**：`test_scripts/test_ragservice.py`
- **测试内容**：
  1. 初始化 RAGService
  2. 添加单个文档
  3. 批量添加 99 个文档
  4. 向量检索模式测试
  5. 关键词检索模式测试
  6. 混合检索模式测试（带 rerank_score）
  7. 不同权重配置测试（0.7/0.3, 0.3/0.7, 0.5/0.5）
  8. 删除单个文档
  9. 批量删除文档
  10. 清理测试数据
