## 二、知识库构建流程

### 2.1 构建脚本说明

**脚本位置**：`build_complete_knowledge_base.py`

**主要功能**：
1. 自动遍历6个企业目录
2. 为每个企业创建独立知识库
3. 自动收集所有文本文件（.txt, .json, .csv, .md）
4. 批量添加文件到知识库
5. 生成知识库元数据索引

### 2.2 构建步骤

#### 步骤1：扫描企业目录
```python
dataset_root = "RAG-Multi-Corpus/datasets"
enterprises = [
    "Aventro Motors",
    "Cendara University",
    "CloudWay-24",
    "TechEdu Academy",
    "Velvera Technologies",
    "ZX Bank"
]
```

#### 步骤2：收集文件
```python
# 支持的文件格式
supported_extensions = ['.txt', '.json', '.csv', '.md']

# 递归扫描目录
for root, dirs, files in os.walk(enterprise_path):
    for file in files:
        if any(file.endswith(ext) for ext in supported_extensions):
            file_list.append(file_path)
```

#### 步骤3：创建知识库
```python
kb = KnowledgeBase(
    kb_name=kb_name,
    kb_path=kb_path,
    chunk_size=500,
    chunk_overlap=50
)
```

#### 步骤4：批量添加文件
```python
result = kb.add_files(file_list)
print(f"成功添加: {result['success']}/{result['total']} 文件")
print(f"总文档数: {result['total_documents']}")
```

#### 步骤5：生成元数据
```python
metadata = {
    "kb_name": kb_name,
    "enterprise": enterprise_name,
    "total_files": result['success'],
    "total_documents": result['total_documents'],
    "created_at": datetime.now().isoformat()
}
```

## 四、构建过程中的问题

### 4.1 重复文档导致的失败

**现象**：部分文件添加失败（6个文件）

**原因**：
- 文件内部包含重复内容块
- 切分后产生相同 MD5
- VectorDB 拒绝插入重复 ID

**失败文件列表**：
1. `Aventro Motors.csv` - 11个重复MD5
2. `Aventro Motors Variants & Pricing.md` - 重复MD5
3. `Careers at CloudWay 24.md` - 重复MD5
4. `Mumbai Inbound & Outbound Flights.md` - 重复MD5
5. `velevra_start.md` - 重复MD5

**影响评估**：
- 失败率：6/248 = 2.4%
- 成功构建：242/248 = 97.6%
- **结论**：对整体知识库质量影响极小

**处理方式**：
- 自动回滚失败的文件
- 记录日志供后续分析
- 其他文件正常添加

### 4.2 CSV 文件的特殊处理

**问题**：CSV 文件包含大量重复行

**示例**：`Aventro Motors.csv` 651个文档块，11个重复

**原因分析**：
- CSV 表格数据可能有重复记录
- 每行转换为文档块时产生相同内容

**当前方案**：
- 自动去重（保留第一个，跳过后续重复）
- 适合实际场景（去重是合理需求）

## 六、使用构建好的知识库

### 6.1 加载知识库

```python
from KnowledgeBase import KnowledgeBase
import json

# 读取元数据
with open("data/knowledge/knowledge_bases.json", "r") as f:
    kb_metadata = json.load(f)

# 加载指定知识库
kb = KnowledgeBase(
    kb_name="aventro_motors",
    kb_path=kb_metadata["aventro_motors"]["kb_path"]
)

print(f"知识库: {kb.kb_name}")
print(f"文件数: {kb_metadata['aventro_motors']['total_files']}")
print(f"文档数: {kb_metadata['aventro_motors']['total_documents']}")
```

### 6.2 检索示例

```python
# 混合检索（推荐）
results = kb.search(
    query="What are the features of Aventro sedan models?",
    mode="hybrid",
    k=5
)

for i, doc in enumerate(results, 1):
    print(f"\n[{i}] {doc.metadata.get('source', 'unknown')}")
    print(doc.page_content[:200])
    if 'rerank_score' in doc.metadata:
        print(f"Rerank Score: {doc.metadata['rerank_score']:.4f}")
```

### 6.3 统计信息

```python
stats = kb.get_statistics()
```

## 七、后续优化建议

### 7.1 性能优化

**并行构建**：
- 当前：单线程顺序构建
- 优化：多进程并行构建多个知识库
- 预期提升：3-5倍速度

**批量 API 调用**：
- 当前：逐个文档调用 embedding API
- 优化：批量调用（最多25个/批）
- 预期提升：减少30% API 调用时间

### 7.2 功能扩展

**增量更新**：
- 支持只添加新文件
- 检测文件变化（MD5）
- 避免重复构建

**版本管理**：
- 记录每次构建的版本号
- 支持回滚到历史版本
- 对比不同版本的差异

### 7.3 质量提升

**文档质量检查**：
- 检测空文档、过短文档
- 检查特殊字符和编码问题
- 自动清洗和格式化

**去重策略优化**：
- 在 RAGService 层面先去重
- 支持相似度去重（不只是完全相同）
- 记录去重日志供分析
