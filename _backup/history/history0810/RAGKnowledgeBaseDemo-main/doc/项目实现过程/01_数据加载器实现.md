## 一、实现目标

实现医疗知识库数据的加载和转换功能，将 JSON 格式的三元组知识图谱数据转换为 LangChain Document 格式，为后续的 VectorDB、KeywordDB 和 RAGService 测试提供标准化数据。

## 二、数据源信息

### 2.1 数据集概述

**数据集名称**：医学知识图谱（Medical Knowledge Graph）

**数据来源**：基于中国人民解放军军事科学院图书馆研发的医学类专业知识库

**数据规模**：
- 三元组总数：82,478 条
- 疾病实体：2,916 个
- 症状实体：1,880 个
- 药品实体：4,563 个
- 手术实体：32 个

**数据位置**：
- JSON文件：`RAGKnowledgeBaseDemo-main\RAGKnowledgeBaseDemo-main\MedicalDataset\triples.json`
- 说明文档：`RAGKnowledgeBaseDemo-main\RAGKnowledgeBaseDemo-main\doc\sampledata_README.md`

### 2.2 数据格式

每条三元组数据格式：
```json
{
    "subject_entity_id": "1340274238220804370",
    "subject_entity_name": "人参茎叶总皂苷胶囊",
    "subject_entity_type": "药品",
    "relation_name": "不良反应",
    "object_entity_id": "1340274222529913101",
    "object_entity_name": "头痛",
    "object_entity_type": "疾病"
}
```

**字段说明**：
- `subject_entity_id`：主体实体ID（雪花算法生成）
- `subject_entity_name`：主体实体名称
- `subject_entity_type`：主体实体类型（药品/疾病/症状/手术）
- `relation_name`：关系名称（如：不良反应、适应症、治疗方法等）
- `object_entity_id`：客体实体ID
- `object_entity_name`：客体实体名称
- `object_entity_type`：客体实体类型

## 三、实现内容

### 3.1 创建文件

**文件路径**：`test_scripts/test_data_loader.py`

**文件功能**：
1. 加载医疗知识图谱 JSON 数据
2. 统计分析数据结构和实体分布
3. 将数据转换为 LangChain Document 格式
4. 支持两种转换模式：三元组模式和实体模式

### 3.2 核心类：MedicalDataLoader

#### 3.2.1 类结构

```python
class MedicalDataLoader:
    def __init__(self, json_path: str)
    def load_data(self)
    def _analyze_data(self)
    def convert_to_documents(self, format_type: str) -> List[Document]
    def _convert_triples_to_documents(self) -> List[Document]
    def _convert_entities_to_documents(self) -> List[Document]
    def get_statistics(self) -> dict
```

#### 3.2.2 主要功能

**（1）数据加载（load_data）**
- 读取 JSON 文件
- 加载所有三元组数据
- 自动触发数据分析

**（2）数据分析（_analyze_data）**
- 统计三元组总数
- 统计各类实体数量（疾病、症状、药品、手术）
- 提取所有关系类型
- 生成统计报告

**（3）三元组模式转换（_convert_triples_to_documents）**

将每条三元组转换为一个 Document：

```python
Document(
    page_content="人参茎叶总皂苷胶囊（药品） 不良反应 头痛（疾病）",
    metadata={
        'md5': '...',
        'source': 'medical_triples.json',
        'data_type': 'triple',
        'subject_entity_id': '...',
        'subject_entity_name': '人参茎叶总皂苷胶囊',
        'subject_entity_type': '药品',
        'relation_name': '不良反应',
        'object_entity_id': '...',
        'object_entity_name': '头痛',
        'object_entity_type': '疾病'
    }
)
```

**优点**：
- 粒度细，适合精确检索
- 每个Document包含完整的三元组信息
- 适合关系型查询

**（4）实体模式转换（_convert_entities_to_documents）**

将每个实体及其所有关系转换为一个 Document：

```python
Document(
    page_content="""
实体名称: 人参茎叶总皂苷胶囊
实体类型: 药品
关系数量: 5

相关关系:
  - 不良反应: 头痛（疾病）
  - 不良反应: 腹泻（疾病）
  - 适应症: 糖尿病（疾病）
  ...
    """,
    metadata={
        'md5': '...',
        'source': 'medical_entities.json',
        'data_type': 'entity',
        'entity_id': '...',
        'entity_name': '人参茎叶总皂苷胶囊',
        'entity_type': '药品',
        'relation_count': 5
    }
)
```

**优点**：
- 实体信息聚合，适合全面了解某个实体
- Document数量较少（约9391个），检索效率高
- 适合"这个药有什么作用"类问题

## 五、技术要点

### 5.1 MD5生成

使用 Python hashlib 库生成唯一标识：
```python
md5_hash = hashlib.md5(content.encode('utf-8')).hexdigest()
```

**作用**：
- 作为 Document 在 VectorDB 和 KeywordDB 中的唯一索引
- 支持文档去重
- 支持文档增删操作

### 5.2 LangChain Document 格式

标准结构：
```python
Document(
    page_content=str,  # 文档内容（用于检索和展示）
    metadata=dict      # 元数据（包含md5和其他信息）
)
```

**设计原则**：
- `page_content`：人类可读的文本，包含完整语义
- `metadata.md5`：必需字段，用作唯一索引
- `metadata.source`：标识数据来源
- 其他 metadata：保留原始结构化信息，便于追溯

### 5.3 两种转换模式的选择

| 特性 | 三元组模式 | 实体模式 |
|------|-----------|---------|
| Document数量 | 82,478 | 9,391 |
| 检索粒度 | 细（单个关系） | 粗（实体全貌） |
| 适用场景 | 精确关系查询 | 实体综合查询 |
| 存储空间 | 较大 | 较小 |
| 检索速度 | 较慢 | 较快 |

**建议**：
- 初期测试：使用**三元组模式**（数据量大，更能测试性能）
- 生产环境：根据实际查询需求选择或混合使用
